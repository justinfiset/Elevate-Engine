Pointer Patching

EEObjectPtr<T> is a lazy handle to an EEObject. It stores a GUID at all times and, once resolved, also stores a std::shared_ptr<T>. The GUID is the serialized identity; the shared pointer is a cache that can be rebuilt by the asset registry.

IEEObjectPtr is the non-typed interface used by the reflection layer. It exposes GetGuid() and SetGuid() so the EngineDataType::ObjectPtr codec can capture a GUID without knowing T. There is currently no virtual Deserialize() on the interface.

Handle states

  • Resolved: m_ptr is non-null. m_guid mirrors m_ptr->GetGuid().
  • Deferred: m_ptr is null and m_guid is valid. The object is looked up on the first dereference.
  • Empty: m_ptr is null and m_guid is invalid. Dereferencing returns nullptr.

Assigning a shared_ptr, calling reset(), or constructing from a shared_ptr enters the resolved state. Constructing from a GUID, or calling SetGuid() with a different GUID, clears m_ptr and enters the deferred state.

Flow

Steps

  1. On capture, EEObjectPtr<T>::Serialize() writes the GUID of the resolved object, or the stored GUID when deferred. The reflection codec writes the same GUID as a string in PropertyField::Value.
  2. On first dereference of a deferred handle, get() calls Detail::ResolveAssetHelper(guid).
  3. ResolveAssetHelper() delegates to ResolveAssetReference(), which calls AssetRegistry::GetAsset<Asset>(guid) and casts the result to EEObject.
  4. AssetRegistry returns a cached instance when one exists. Otherwise, for an on-disk entry, it creates the registered type through TypeRegistry, deserializes the JSON file, restores the GUID from the indexed m_guid, and calls OnLoad().
  5. EEObjectPtr statically casts the EEObject back to T and calls UpdateGuid(). A successful lookup caches the result in m_ptr; a failed lookup leaves m_ptr null and clears m_guid.
Warning
Only Asset-derived objects can be resolved this way. EEObject constructors generate a GUID but do not register the object globally; the old ObjectRegistry design no longer exists. An EEObjectPtr<GameObject> that is only assigned a GUID cannot be rebuilt unless the target is indexed as an asset.
Restoring EngineDataType::ObjectPtr from JSON is not implemented. ValueCodec::Apply logs an error and returns false, so a deferred pointer must receive its GUID through code (Guid constructor or SetGuid()) before lazy resolution can run.
Note
A failed lookup is terminal for that handle: UpdateGuid() resets the GUID when m_ptr is null, so subsequent dereferences do not retry the registry.
